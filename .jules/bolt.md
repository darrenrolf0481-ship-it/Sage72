## 2026-09-06 - Soul Vault File Read & Conflict Sweep Optimization
**Learning:** Repeated `json.load()` calls on JSON memory stores (`sage_soul.json`) per recall query created a major bottleneck (1.32ms per recall query on 73 records, 75.5ms on 5k records). Adding an `mtime`-based file cache with pre-computed lowercased search strings reduced recall latency to 0.29ms (4.46x throughput boost) and 23.4ms on 5k records (3.2x throughput boost). Additionally, background dream daemons had an $O(N^2)$ duplicate proposal loop that was refactored to an $O(N)$ hash-map grouping.
**Action:** Always check if JSON data stores or database records read on hot paths can be cached with `mtime` invalidation, and audit background tasks for quadratic nested loop comparisons.

## 2026-09-14 - Soul Memory Search & Associative Pathway Short-Circuit Optimization
**Learning:** Nested list comprehensions (`any(kw in tag for tag in tags)`) and re-evaluating `.lower()` on graph nodes during search loops were major CPU hotspots during memory recall. Nesting tag matching inside parent searchable text checks (`if kw in searchable: if tags_searchable and kw in tags_searchable:`), pre-computing `tags_searchable` strings & salience score multipliers during `_SOUL_CACHE` indexing, and pre-lowercasing graph keys reduced standard vault search latency from 0.308ms to 0.117ms (2.63x throughput boost) and 5k scaled vault search from 23.86ms to 11.21ms (>2.1x throughput boost).
**Action:** In search indexing, pre-calculate static multipliers and composite substring fields during cache initialization, and short-circuit tag or metadata scoring behind parent text containment checks.
