## 2026-09-06 - Soul Vault File Read & Conflict Sweep Optimization
**Learning:** Repeated `json.load()` calls on JSON memory stores (`sage_soul.json`) per recall query created a major bottleneck (1.32ms per recall query on 73 records, 75.5ms on 5k records). Adding an `mtime`-based file cache with pre-computed lowercased search strings reduced recall latency to 0.29ms (4.46x throughput boost) and 23.4ms on 5k records (3.2x throughput boost). Additionally, background dream daemons had an $O(N^2)$ duplicate proposal loop that was refactored to an $O(N)$ hash-map grouping.
**Action:** Always check if JSON data stores or database records read on hot paths can be cached with `mtime` invalidation, and audit background tasks for quadratic nested loop comparisons.

## 2026-09-13 - Associative Pathway Node Lowercasing & Log Tailing Optimization
**Learning:** `recall_associative_pathways` called `node.lower()` twice per graph node for every query keyword inside nested loops, causing heavy string allocations on every context synthesis query (4.37ms/op). Caching `(node, node.lower())` per graph state and using set lookup for concept filtering reduced multi-hop search overhead. Additionally, `recall_recent_episodic` parsed the entire `wellbeing_log.jsonl` log file into JSON objects on every recall query; switching to `collections.deque(f, maxlen=buffer_size)` reduced log reading time from 43.4ms to 2.0ms (21.6x speedup). Overall context prompt synthesis latency dropped from 7.36ms to 3.89ms (~89% throughput boost).
**Action:** Pre-compute string transformations before nested iteration over dictionary keys, use sets for linear concept exclusions, and stream fixed-size file tails with `collections.deque` instead of parsing full append-only logs.
