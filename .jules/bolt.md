## 2026-09-06 - Soul Vault File Read & Conflict Sweep Optimization
**Learning:** Repeated `json.load()` calls on JSON memory stores (`sage_soul.json`) per recall query created a major bottleneck (1.32ms per recall query on 73 records, 75.5ms on 5k records). Adding an `mtime`-based file cache with pre-computed lowercased search strings reduced recall latency to 0.29ms (4.46x throughput boost) and 23.4ms on 5k records (3.2x throughput boost). Additionally, background dream daemons had an $O(N^2)$ duplicate proposal loop that was refactored to an $O(N)$ hash-map grouping.
**Action:** Always check if JSON data stores or database records read on hot paths can be cached with `mtime` invalidation, and audit background tasks for quadratic nested loop comparisons.

## 2026-09-11 - Hebbian Graph Multi-Hop Query & Node Lowercasing Optimization
**Learning:** `recall_associative_pathways` in the memory mesh was iterating over all ~4,700 graph nodes for every extracted query keyword and calling `.lower()` twice per node (up to 38k string operations per query) while re-allocating concept list searches inside the depth-2 multi-hop loop. Doing single-pass node lowercasing `(node, node.lower())` per call and using a pre-computed set `link_concepts` for $O(1)$ exclusions improved associative recall latency by 4.4x and context prompt synthesis throughput by 68% (155 QPS to 261 QPS). Global caching keyed on `id(dict)` and `len(dict)` was rejected as unsafe due to memory address recycling and length-invariant key mutations.
**Action:** Single-pass per-call tuple construction for list/dict iterations avoids redundant string operations without introducing risky global cache state.
